# Project walkthrough

Shiyu is a local Windows application that reads supported WeChat 4.x databases,
builds an independent archive, and exports one selected conversation to Word.
It implements the requested workflow using public format research; it does not
contain the referenced commercial application's installer or proprietary code.

## Entry points and configuration

| File | Responsibility |
| --- | --- |
| `main.py` | Starts the app, reads local configuration, and handles `--source`, `--data`, `--archive`, `--demo`, and the packaged self-test option. |
| `start.bat` | Starts the packaged EXE when available, otherwise starts the Python source without a console window. |
| `setup.ps1` | Creates the project virtual environment and installs runtime and development dependencies. |
| `build.ps1` | Builds the Windows application with PyInstaller, collects notices, and copies program files into `dist/Shiyu` while preserving user data. It isolates DLL search paths to prevent unrelated ICU libraries from breaking Qt. |
| `requirements.txt` | Pins runtime dependencies. |
| `requirements-dev.txt` | Adds pytest and PyInstaller for testing and packaging. |
| `local.example.json` | Shareable example of the source-directory configuration. |
| `local.json` | Private, ignored configuration for this installation. |
| `.gitignore` | Excludes environments, generated files, archives, exports, and local configuration from Git. |
| `Shiyu.spec` | Generated PyInstaller build description; regenerated by the build script and ignored by Git. |
| `README.md` | Setup, usage, supported behavior, and current limitations. |
| `THIRD_PARTY_NOTICES.md` | Attribution and dependency licensing information. |

## Application modules

| File | Responsibility |
| --- | --- |
| `wxarchive/__init__.py` | Marks the Python package and declares its version. |
| `wxarchive/simple_ui.py` | The actual desktop window: source directory, process detection, conversation dropdown, progress/cancel controls, offline archive selection, and DOCX export. Same-name contacts include their IDs so the selection is unambiguous. |
| `wxarchive/widgets.py` | Shared styles, icon drawing, small widget helpers, and the `Job` background worker. It also retains an older `ImportDialog` that is not exposed by the current simplified window. |
| `wxarchive/discovery.py` | Resolves an account directory or `db_storage`, finds message/contact/resource databases, and infers the user's WeChat ID from the account folder. Multiple accounts require an explicit account selection. |
| `wxarchive/capture.py` | Watches the current user's main Weixin processes and temporarily instruments supported SHA-512 code through Frida. Candidate master keys are accepted only after authenticating an actual database page. Connections detach on completion, cancellation, or timeout. |
| `wxarchive/win_keys.py` | Reads eligible Weixin memory regions to find and validate image keys. It can also recognize per-database derived-key patterns. The current UI uses the image-key path and waits for opening a photo to make that key available. |
| `wxarchive/crypto.py` | Authenticates and decrypts supported SQLCipher pages into private copies, verifies and applies committed WAL transactions, checks SQLite integrity, and rejects inputs that change during the read. |
| `wxarchive/messages.py` | Decompresses Zstandard message payloads, interprets message types and XML, formats quoted/forwarded content, extracts media metadata, and identifies quoted images by original message ID. |
| `wxarchive/pictures.py` | Matches messages to local image files, decodes supported XOR/V1/V2 containers, tries WXGF-to-image conversion through FFmpeg, and normalizes images to PNG. It prefers originals and labels thumbnail fallbacks. |
| `wxarchive/archive.py` | Coordinates database copying, contact and sender resolution, message parsing, picture restoration, and creation of the standalone SQLite archive. Its `Archive` class provides queries for the UI and exporter. |
| `wxarchive/docx_export.py` | Writes chronological Word documents with dates, senders, recipients, message text, and embedded pictures. Quoted images match an exact original message in the same conversation. Existing archives use the latest quote parser when exported again. |
| `wxarchive/common.py` | Shared errors, cooperative cancellation, read-only SQLite connections, SQL identifier quoting, and safe Windows filenames. |
| `wxarchive/demo.py` | Generates clearly labelled synthetic conversations for development. It never substitutes demo records for real imports. |
| `wxarchive/selftest.py` | Exercises the packaged application's dependencies and a synthetic export, including normal and quoted images, without accessing WeChat. Writes a JSON pass/fail report. |

## How the application runs

1. `main.py` creates the window. A configured source starts process detection.
2. `capture.py` waits for WeChat startup/login and verifies a database master key.
3. On reading chats, `win_keys.py` waits for an image key if V2 images are present.
4. `archive.py` asks `crypto.py` for authenticated database snapshots, including
   committed WAL data. It reads contacts and each message shard, then uses
   `messages.py` and `pictures.py` to create an independent archive.
5. The dropdown selects a conversation by its stored ID.
6. `docx_export.py` reads that conversation from the archive and writes a DOCX.
   Photos are embedded in the file, so the document needs no sidecar image folder.

Long operations run in a `Job` QThread. Progress returns to the window through
Qt signals. Cancellation is cooperative: processing stops at checkpoints and
temporary files are cleaned up before the operation finishes.

Process detection alone cannot read encrypted records. The database acquisition
step temporarily instruments WeChat; image-key scanning uses read-only process
memory access. These are two separate mechanisms and two separate key types.

## The archive database

| Table | Contents |
| --- | --- |
| `meta` | Source information, account ID, import timestamp, counts, and warnings. |
| `conversations` | Conversation IDs, display names, group flags, message counts, and latest timestamps. |
| `messages` | Conversation/sender identity, time, readable text, original payload, original message IDs, and media metadata. |
| `pictures` | Restored PNG bytes or an explicit failure reason, keyed by archive message ID. |

An archive can be reopened and exported without logging into WeChat again.
It is a readable local database, not an encrypted backup. Captured database and
local-image keys are not deliberately persisted as configuration or logs;
original message payloads retained in the archive can themselves contain media
metadata such as CDN parameters.

## Generated directories

- `.venv/`: the development Python interpreter and installed dependencies.
- `__pycache__/`, `.pytest_cache/`: generated Python and pytest caches. Some
  bytecode files may remain from earlier removed modules; they are not current source.
- `artifacts/pyinstaller-work/` (older builds used `build/`): PyInstaller dependency analysis and intermediate build files.
- `artifacts/`: build logs, self-test reports, synthetic previews, public research
  reference copies, and staging files. These are development outputs, not source.
- `dist/Shiyu/`: the runnable application. `Shiyu.exe` needs its `_internal/`
  dependencies alongside it; distribute the application folder together.
- `dist/Shiyu/data/`: the packaged application's default archives and exports.
- `data/`: the source-run default data directory and locally generated exports.
  `--data` can override either default.

These generated directories and private records are excluded from the source repository.

## Dependencies and practical limits

PySide6 provides Qt widgets and threads; psutil discovers processes; Frida handles
temporary instrumentation; cryptography provides AES; zstandard decompresses
messages; Pillow processes images; python-docx writes Word files; and
imageio-ffmpeg supplies the FFmpeg executable used for some WXGF images.

Compatibility is verified for the tested Windows WeChat version, not every 4.x
release. A local thumbnail cannot be turned into an unavailable original image.
Voice/video transcription, deleted-message recovery, and cloud-media downloading
are outside this application's current scope. Automated DOCX pagination review
remains unavailable in the development environment without the required renderer.
